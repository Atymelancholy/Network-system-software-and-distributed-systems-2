# Network-system-software-and-distributed-systems-2
## Лабораторная работа №5 — ICMP и IP
- Реализовать параллельный ping нескольких хостов: каждый поток пингует свой хост.
- Чтобы потоки не забирали чужие ответы из входного буфера, использовать опцию MSG_PEEK (в тексте опечатка «MSG_PEEG»), удаляя пакет только после проверки, что ответ предназначен данному потоку.
- Добавить определение маршрута до узла (аналог traceroute): метку времени отправки вкладывать в тело ping-запроса, при ответе вычислять время передачи.
- Обрабатывать разные ситуации: «время жизни истекло», «ping-ответ», «хост недостижим».
- Преобразовать ping для атаки Smurf (подмена адреса источника на адрес атакуемого узла) и продемонстрировать на атакуемом узле через Wireshark.

## Лабораторная работа №6 — широковещательный и многоадресный режим
- Разработать одноранговый чат на UDP или IP с передачей сообщений через broadcast и multicast.
- Для multicast предусмотреть самостоятельный выход из группы и принудительное игнорирование хоста другими участниками.
- Программа должна автоматически определять сетевые параметры интерфейса: IP-адрес, маску, широковещательный адрес, а также находить и выводить список IP-адресов запущенных приложений.

## Лабораторная работа №7 — MPI: парные коммуникации, коллективные операции, группы и коммуникаторы
- Программа умножения матриц достаточно большого размера (время работы ~10–50 сек) с использованием парных операций.
- Реализовать 2 варианта: блокирующий и неблокирующий режимы передачи, замерить время; неблокирующий должен дать заметный прирост производительности.
- Запускать минимум на 3 компьютерах.

## Лабораторная работа №8 — MPI: групповые и файловые операции
- Добавить в программу из ЛР №7 коллективные операции.
- Программа создаёт произвольное количество групп (задаётся из командной строки) и включает в них случайное число процессов; каждая группа умножает матрицы.
- Замерить время вычисления в каждой группе, вывести на экран и сравнить со временем на парных операциях.
- Групповые операции с файлами: исходные данные для умножения задаются из 2 файлов, доступных всем узлам по сети; процессы одновременно читают свою порцию данных по своей координате/rank.
- Каждый процесс выводит результаты умножения в файл, принадлежащий соответствующей группе.
- Необязательно: запуск на кластере через PBS / PBS Torque.
